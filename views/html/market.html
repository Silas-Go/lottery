A

同步删除缓存

请求内完成
  1. MySQL 提交
  2. Redis DEL
  3. 返回响应

响应等待删缓存；Redis 的耗时和失败会进入请求链。

这里的失败意味着什么？

库存事务已经提交，删缓存失败不会自动回滚库存，仍需重试失效。

B

Outbox + MQ

后台完成失效
  1. 事务 + Outbox 提交
  2. 返回响应
事务提交后，后台继续

Outbox 发布器 → MQ → 消费者 → Redis DEL

响应不等待删缓存；要观察旧读窗口及后台恢复。

为什么需要 Outbox？

库存更新与待失效事件一起提交，让后续失效和重试有可靠记录。
