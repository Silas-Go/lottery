IMPLEMENTATION · RESULT ANALYSIS

查询路径实现与结果归因

两轮结果已冻结
01
同一个返回对象MaterialDetailDTO

两条路径最终返回同一份星髓详情。它由基础资料、组成材料、交易统计和评分聚合组成。

02
MySQL Direct 做了什么每次执行 4 条真实 SQL

依次读取基础 JOIN、组成列表、交易聚合和评分聚合，再组装最终 DTO；没有用延时函数人为制造差距。

03
Cache Aside 做了什么先查 Redis，必要时再查 MySQL

命中时直接返回完整 DTO；未命中时按材料加锁并双检，执行 4 条 SQL 后回填 Redis。Redis 异常时会降级读取 MySQL。

根据同条件结果判断主要瓶颈

如果旁路缓存同时表现为更高的目标完成率、更低的实际请求延迟，并且 SSE 中 SQL 数下降、缓存命中率上升，才说明“命中后跳过数据库查询与 DTO 组装”是这轮差异的主要原因。若 Socket Errors 或需求侧延迟仍高，则还要检查连接承载和投递欠账，不能把所有差异都归因于缓存。
